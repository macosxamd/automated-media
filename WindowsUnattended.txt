Create unattended iso with drivers Windows

Creating a custom Windows ISO that includes an "unattended" setup file (autounattend.xml) and integrated drivers is a great way to streamline installations.

To do this effectively, I recommend using MSMG Toolkit or NTLite (the free version covers the basics). If you prefer a manual approach using Microsoft's native tools, follow the guide below.
🛠 Prerequisites

    Windows ADK: Install the Deployment Tools and User State Migration Tool (USMT).

    Windows ISO: A clean image of Windows 10 or 11.

    Drivers: Download the .inf versions of your drivers (usually extracted from .exe or .zip files).

1. Prepare your Workspace

Create three folders on your drive (e.g., in C:\ISO_Build):

    Mount: Where the Windows image will be "opened."

    Drivers: Where you store your .inf driver files.

    ISO_Files: Where you extract the contents of your original Windows ISO.

2. Mount and Integrate Drivers

You will use the Deployment Image Servicing and Management (DISM) tool via PowerShell or Command Prompt (Run as Administrator).
Mount the Image

First, identify which index (version) of Windows you want to modify (e.g., Home, Pro):
PowerShell

dism /Get-WimInfo /WimFile:C:\ISO_Build\ISO_Files\sources\install.wim

Mount the desired index (replace 1 with your choice):
PowerShell

dism /Mount-Wim /WimFile:C:\ISO_Build\ISO_Files\sources\install.wim /Index:1 /MountDir:C:\ISO_Build\Mount

Add Drivers

This command injects all drivers found in your folder and its subfolders:
PowerShell

dism /Image:C:\ISO_Build\Mount /Add-Driver /Driver:C:\ISO_Build\Drivers /Recurse

Save and Unmount
PowerShell

dism /Unmount-Wim /MountDir:C:\ISO_Build\Mount /Commit

3. Create the Unattended File

To make the installation "unattended" (skipping region selection, EULA, and user creation), you need an autounattend.xml file.

    Easy Way: Use the Windows Answer File Generator.

    Placement: Once you generate the .xml file, rename it to autounattend.xml and place it in the root of your ISO_Files folder (the same level as setup.exe).

4. Package the ISO

Finally, turn your modified folder back into a bootable ISO file using the oscdimg tool included in the ADK:
PowerShell

oscdimg -n -m -bC:\ISO_Build\ISO_Files\boot\etfsboot.com C:\ISO_Build\ISO_Files C:\ISO_Build\Custom_Windows.iso

💡 Pro-Tips

    Driver Format: DISM only accepts .inf files. If your driver is an .exe, try extracting it with 7-Zip or WinRAR first.

    Test First: Always test your new ISO in a Virtual Machine (like VirtualBox or VMware) before wiping a physical drive.

    Updates: You can use the same DISM "Mount" method to integrate .msu Windows Update files to ensure your ISO is fully patched.

I want to make the answer manually using System Image Manager

Using Windows System Image Manager (WSIM)—part of the Windows ADK—is the most "official" way to do this. It validates your XML against the specific Windows image you are using, ensuring you don't use deprecated settings.

Here is the workflow to create your autounattend.xml manually.
1. Catalog File Generation

Before you can edit settings, WSIM needs a Catalog (.clg) file to understand what settings are available for your specific Windows version.

    Open Windows System Image Manager.

    Go to File > Select Windows Image.

    Navigate to your extracted ISO folder, go to sources, and select install.wim.

    If prompted that a catalog file cannot be found, click Yes to create one.

        Note: This may take several minutes. It creates a .clg file in the sources folder.

2. Create the Answer File

    Go to File > New Answer File.

    You will see seven "Passes" in the Answer File pane. These represent different stages of the installation.

Key Components to Add

Right-click the following components in the Windows Image pane and select Add Setting to Pass...:
Component	Pass	Purpose
amd64_Microsoft-Windows-International-Core-WinPE	1 windowsPE	Sets language, keyboard, and locale.
amd64_Microsoft-Windows-Setup	1 windowsPE	Handles disk partitioning and Product Key.
amd64_Microsoft-Windows-Shell-Setup	4 specialize	Sets computer name and time zone.
amd64_Microsoft-Windows-Shell-Setup	7 oobeSystem	Creates user accounts and skips the EULA/Intro.
3. Essential Configurations

Once added, select the component in the Answer File pane and edit its properties:
Language & Locale (Pass 1)

In Microsoft-Windows-International-Core-WinPE:

    InputLocale: e.g., en-US

    SystemLocale: en-US

    UILanguage: en-US

    SetupUILanguage: Set UILanguage here as well to skip the initial language picker.

Automated Partitioning (Pass 1)

In Microsoft-Windows-Setup > DiskConfiguration > Disk:

    Set WillShowUI to OnError.

    Right-click Disk to Insert New Partition. You must define the ID, size, and format (NTFS/FAT32) here.

    Warning: This will wipe the destination disk automatically.

User Accounts (Pass 7)

In Microsoft-Windows-Shell-Setup > UserAccounts > LocalAccounts:

    Right-click LocalAccounts and Insert New LocalAccount.

    Fill in the Name, Group (Administrators), and DisplayName.

    Set the password under the Password sub-node.

Skip "OOBE" (Pass 7)

In Microsoft-Windows-Shell-Setup > OOBE:

    Set HideEULAPage, HideLocalAdministrationPage, and HideOnlineIDFirstRunExperience to true.

    Set ProtectYourPC to 1 (Recommended settings).

4. Validation and Saving

    Go to Tools > Validate Answer File.

    Check the Messages pane at the bottom.

        Warnings (yellow) are usually fine (e.g., "setting not used").

        Errors (red) must be fixed, or the setup will crash.

    Go to File > Save Answer File As.

    Name it exactly autounattend.xml.

5. Final Step

Place the autounattend.xml file in the root directory of your USB drive or the folder you are using to build your ISO. When Windows Setup boots, it automatically looks for this filename in the root.

I want to archive the procedure for teaching purposes so do all the needed procedure for both

Since you are archiving this for teaching purposes, it is helpful to contrast the two partitioning styles. Modern systems (Windows 10/11) almost exclusively use UEFI (GPT), while older hardware or specific legacy VMs use BIOS (MBR).

Here is the manual configuration procedure for both within Windows System Image Manager (WSIM).
1. Global Setup (Common to Both)

Before defining partitions, you must add the component to Pass 1 windowsPE:

    Component: amd64_Microsoft-Windows-Setup_neutral

    Path: DiskConfiguration -> Disk

    Action: Set DiskID to 0 and WillShowUI to OnError.

2. Option A: UEFI / GPT Partitioning

UEFI requires a specific layout to boot Windows correctly, including the EFI System Partition (ESP) and the Microsoft Reserved (MSR) partition.
Disk Settings

    SystemImageManager > Disk: Set ConfigID to 0.

Create Partitions (Right-click CreatePartitions > Insert New Partition)

    Windows RE (Recovery):

        Order: 1 | Size: 500 | Type: Primary

    System (EFI):

        Order: 2 | Size: 100 | Type: EFI

    MSR (Microsoft Reserved):

        Order: 3 | Size: 128 | Type: MSR

    Windows (OS):

        Order: 4 | Extend: true | Type: Primary

Format Partitions (Right-click ModifyPartitions > Insert New Modification)
Order	PartitionID	Format	Label
1	1	NTFS	WinRE
2	2	FAT32	System
3	3	(None)	(None)
4	4	NTFS	Windows

    Crucial: For Partition 4 (Windows), set InstallToDriveID to 0 and InstallToPartitionID to 4 under the UserData or OSImage settings to tell Windows where to land.

3. Option B: BIOS / MBR Partitioning

MBR is simpler but limited. It usually involves a small "System Reserved" boot partition and a main OS partition.
Disk Settings

    SystemImageManager > Disk: Set ConfigID to 0.

Create Partitions

    System Reserved:

        Order: 1 | Size: 500 | Type: Primary

    Windows (OS):

        Order: 2 | Extend: true | Type: Primary

Format Partitions
Order	PartitionID	Format	Label	Active
1	1	NTFS	System	true
2	2	NTFS	Windows	false

    Note: In MBR, the boot partition (Partition 1) must be marked Active: true.

4. Summary Table for Comparison
Feature	UEFI (GPT)	BIOS (MBR)
Max Partitions	128	4 Primary
Boot Partition	FAT32 (EFI)	NTFS (System Reserved)
MSR Required?	Yes	No
Max Disk Size	9.4 Zettabytes	2 Terabytes
WSIM Pass	1 windowsPE	1 windowsPE
5. Teaching Checklist (The "Archive" Notes)

When teaching this, emphasize these three common points of failure:

    The Catalog (.clg) Match: The architecture (amd64 vs x86) of the technician PC and the target ISO should ideally match to avoid catalog generation errors.

    Order vs ID: In WSIM, Order refers to the creation sequence, while PartitionID in the ModifyPartitions section must match the ID assigned during creation.

    Wiping Data: Remind students that setting WillShowUI to Never or OnError with these disk settings will wipe the target drive without a confirmation prompt.

I want the procedure to add drivers and the procedure to create a completely automated installation.

To create a fully automated Windows installation for teaching purposes, you must combine two distinct workflows: Image Servicing (adding drivers to the physical files) and Answer File Creation (automating the setup logic).
Part 1: Integrating Drivers (Offline Servicing)

This procedure uses DISM to inject drivers directly into the install.wim file so that Windows has the necessary hardware support (like storage or network controllers) the moment it boots.
1.1 Prepare the Environment

    Extract your Windows ISO to C:\Build\ISO.

    Place all extracted .inf drivers in C:\Build\Drivers.

    Create an empty folder at C:\Build\Mount.

1.2 Injecting the Drivers

Open PowerShell or Command Prompt as Administrator:

    Mount the Image:
    PowerShell

    dism /Mount-Wim /WimFile:C:\Build\ISO\sources\install.wim /Index:1 /MountDir:C:\Build\Mount

    Add Drivers:
    PowerShell

    dism /Image:C:\Build\Mount /Add-Driver /Driver:C:\Build\Drivers /Recurse

    Commit and Unmount:
    PowerShell

    dism /Unmount-Wim /MountDir:C:\Build\Mount /Commit

Part 2: Creating the Automated Answer File (WSIM)

To make the installation "Zero Touch," use the Windows System Image Manager (WSIM) to create an autounattend.xml.
2.1 The "Zero Touch" Requirements

In WSIM, you must configure these four areas to ensure no human interaction is required:
A. Disk Automation (Pass 1 windowsPE)

    Component: amd64_Microsoft-Windows-Setup > DiskConfiguration

    Setting: Set WillShowUI to Never.

    Logic: You must define the partitions (as detailed in the previous step). If the installer finds a valid partition structure and WillShowUI is Never, it will not stop to ask where to install.

B. Image Selection (Pass 1 windowsPE)

    Component: amd64_Microsoft-Windows-Setup > UserData

    Setting: AcceptEula = true.

    Component: OSImage > InstallFrom > MetaData

    Setting: If your .wim has multiple versions (Pro, Home), add a metadata check (e.g., Key = /IMAGE/NAME, Value = Windows 10 Pro) so the installer doesn't ask which version to install.

C. Computer Identity (Pass 4 specialize)

    Component: amd64_Microsoft-Windows-Shell-Setup

    Setting: ComputerName = * (generates a random name) or a specific string.

    Setting: TimeZone = Eastern Standard Time (or your local zone).

D. User & OOBE Automation (Pass 7 oobeSystem)

This bypasses the "Hi there" screens and privacy settings.

    Component: amd64_Microsoft-Windows-Shell-Setup > OOBE

    Settings: * HideEULAPage: true

        HideLocalAdministrationPage: true

        HideOnlineIDFirstRunExperience: true

        HideWirelessSetupInOOBE: true

        ProtectYourPC: 1

    Component: UserAccounts > LocalAccounts

    Action: Add at least one user account with a password, otherwise, the setup will stop at the "Create Account" screen.

Part 3: Deployment

To "marry" these two procedures for a teaching lab, follow these final steps:

    Save the File: In WSIM, save your file as autounattend.xml.

    Placement: Copy autounattend.xml to the root of your extracted ISO folder (C:\Build\ISO\).

    ISO Creation: Use oscdimg to wrap the folder back into a bootable file:
    PowerShell

    oscdimg -n -m -bC:\Build\ISO\boot\etfsboot.com C:\Build\ISO C:\Build\Automated_Windows.iso

Summary for Archiving
Stage	Tool	Purpose
Driver Integration	DISM	Ensures the OS recognizes hardware (Storage/NIC).
Pass 1 Automation	WSIM	Skips Disk Selection, Language, and EULA.
Pass 4/7 Automation	WSIM	Skips User Creation, Privacy Settings, and Region.
Final Mastering	Oscdimg	Creates the final bootable media.

This combination ensures that once the technician boots from the ISO, they can walk away and return to a finished Windows desktop.

GUIDE: CREATING AN UNATTENDED WINDOWS ISO WITH INTEGRATED DRIVERS
================================================================================

This guide outlines the professional procedure for creating a "Zero Touch" 
Windows installation media using the Windows ADK and DISM.

--------------------------------------------------------------------------------
1. PREPARATION
--------------------------------------------------------------------------------
Create the following directory structure:
C:\Build\ISO      - Extract your original Windows ISO here.
C:\Build\Drivers  - Place all extracted (.inf) drivers here.
C:\Build\Mount    - Create an empty folder to mount the image.

Ensure the Windows ADK (Deployment Tools) is installed.

--------------------------------------------------------------------------------
2. INTEGRATING DRIVERS (OFFLINE SERVICING)
--------------------------------------------------------------------------------
Run PowerShell as Administrator.

# Identify the Index of the Windows version you want (e.g., Pro, Home)
dism /Get-WimInfo /WimFile:C:\Build\ISO\sources\install.wim

# Mount the specific Index (replace '1' with your desired index)
dism /Mount-Wim /WimFile:C:\Build\ISO\sources\install.wim /Index:1 /MountDir:C:\Build\Mount

# Inject drivers from the folder (recursive)
dism /Image:C:\Build\Mount /Add-Driver /Driver:C:\Build\Drivers /Recurse

# Save changes and unmount
dism /Unmount-Wim /MountDir:C:\Build\Mount /Commit

--------------------------------------------------------------------------------
3. CREATING THE ANSWER FILE (autounattend.xml)
--------------------------------------------------------------------------------
Open "Windows System Image Manager" (WSIM).
Select File > Select Windows Image and choose the install.wim.
Generate a Catalog file if prompted.

KEY SETTINGS TO ADD:

PASS 1 - WINDOWSPE:
- amd64_Microsoft-Windows-Setup / DiskConfiguration:
    * WillShowUI: Never
- amd64_Microsoft-Windows-Setup / DiskConfiguration / Disk:
    * DiskID: 0
    * WillEraseDisk: true
- amd64_Microsoft-Windows-Setup / UserData:
    * AcceptEula: true

PARTITIONING (UEFI Example):
- Create Partition 1: Type=Primary, Size=500 (WinRE)
- Create Partition 2: Type=EFI, Size=100 (System)
- Create Partition 3: Type=MSR, Size=128 (MSR)
- Create Partition 4: Type=Primary, Extend=true (Windows)

PARTITIONING (BIOS Example):
- Create Partition 1: Type=Primary, Size=500 (System Reserved), Active=true
- Create Partition 2: Type=Primary, Extend=true (Windows)

PASS 4 - SPECIALIZE:
- amd64_Microsoft-Windows-Shell-Setup:
    * ComputerName: *
    * TimeZone: [Your Time Zone]

PASS 7 - OOBESYSTEM:
- amd64_Microsoft-Windows-Shell-Setup / OOBE:
    * HideEULAPage: true
    * HideLocalAdministrationPage: true
    * HideOnlineIDFirstRunExperience: true
    * HideWirelessSetupInOOBE: true
    * ProtectYourPC: 1
- amd64_Microsoft-Windows-Shell-Setup / UserAccounts / LocalAccounts:
    * Create a New Local Account and add to 'Administrators' group.

--------------------------------------------------------------------------------
4. GENERATING THE ISO
--------------------------------------------------------------------------------
1. Save the Answer File as 'autounattend.xml' in the root of C:\Build\ISO.
2. Open the "Deployment and Imaging Tools Environment" as Administrator.
3. Run the following command:

oscdimg -n -m -bC:\Build\ISO\boot\etfsboot.com C:\Build\ISO C:\Build\Custom_Windows.iso

--------------------------------------------------------------------------------
5. TEACHING TIPS
--------------------------------------------------------------------------------
- Ensure drivers are .inf format. .exe installers will not work with DISM.
- Always validate the XML in WSIM (Tools > Validate) to check for missing required fields.
- For UEFI, the disk must be GPT. For BIOS, it must be MBR.
